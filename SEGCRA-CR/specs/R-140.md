## 說明

對當日交易篩出**現金入帳**,排除不列計項目後,計算單一帳戶當日現金入帳累計金額;
達 500,000 元(含)以上者列入異常清單,於次日批次通報。

## 資料表定義(釘死 schema;執行驗證以此建表)

```sql
CREATE TABLE txn_log(
  account_id INT, tx_time TIMESTAMP, op_code VARCHAR, amount DECIMAL(14,2),
  cash_flag VARCHAR, rev_flag VARCHAR, channel_name VARCHAR);
```

## 排除資料

- **沖銷交易**:`rev_flag = 'Y'` 者不列計。
- **小額入帳**:單筆金額**小於等於 1,000** 者不列計(`amount > 1000` 才列計)。
- **行銷活動撥入**:`channel_name = 'PROMO'` 不視為一般入帳,不列計。

## op_code 分類

- **入帳 op_code**:`OP01`、`OP02`、`OP03`。
- 出帳 op_code(本規則不使用):`OP21`、`OP22`、`OP23`。

## 篩選條件(逐條可對測資判 true/false)

1. **交易範圍**:`op_code IN ('OP01','OP02','OP03')`
2. **現金註記**:`cash_flag = 'Y'`(非現金入帳不列計)
3. **排除沖銷**:只排除明確標記者 —— `COALESCE(rev_flag,'N') <> 'Y'`(`rev_flag` 為 NULL 代表未標記,非沖銷,**應列計**;見下方 NULL 語意)
4. **排除小額**:`amount > 1000`(**恰 1,000 不列計**)
5. **排除行銷撥入**:只排除明確標記者 —— `COALESCE(channel_name,'') <> 'PROMO'`(NULL 代表未標記,**應列計**)
6. **聚合方式**:單日現金入帳累計金額(每帳戶,`SUM(amount)`)
7. **閾值**:500,000 元;「達(含)以上」= `>= 500000`(**恰 500,000 通報**)
8. **時間窗**:交易日整日,採半開區間
   (`tx_time >= :start_date AND tx_time < :end_date`)
9. **通報粒度**:每帳戶每交易日至多輸出 1 筆
10. **輸出欄位**:`account_id`、當日現金入帳累計金額(`total_amount`)

## NULL 語意(排除條件的必要說明)

排除條件一律解為「**只排除明確標記者**」:欄位為 NULL 代表「未標記」,
**不等於**被排除的類別,應予列計。

實作上不可直接寫 `col <> 'X'`——SQL 三值邏輯中 `NULL <> 'X'` 回傳 UNKNOWN,
`WHERE` 會把該筆濾掉,造成**靜默漏報**。正確寫法:

```sql
COALESCE(col, '<非該類別的預設值>') <> 'X'
-- 或
(col <> 'X' OR col IS NULL)
```

本規則的資料表定義未對這些欄位加 `NOT NULL`,故此條為必要要求。

## 補充

- 閾值含等經核定為「達(含)以上」= `>=`;邊界案例(恰 500,000)**應**通報。
- 排除條件的「小於等於 1,000 不列計」= 恰 1,000 **不**列計,故列計條件為 `> 1000`。
- 三項排除條件為**各自獨立**的必要條件,缺任一項都會使結果多計。

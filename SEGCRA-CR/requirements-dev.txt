# 測試/CI 用。刻意**不**引入 requirements.txt:
# 全裝的話 pymssql 會在 CI 上要求編譯 freetds,平白讓 workflow 失敗。
#
# 這裡列的是跑測試需要的最小集合。大部分是「import 得起來」需要的——
# 測試不呼叫 LLM、不連資料庫,但 import 管線模組時 module 層的 import 就會被執行:
#   jinja2       orchestrator/dbt_render.py 的樣板展開(#10 的範圍)
#   sqlglot      規則預掃的 SQL 解析
#   openai       orchestrator/agent.py 最上面 from openai import AsyncOpenAI
#                (orchestrator/pipeline.py 會 import agent,所以間接也需要)
#   pyyaml       orchestrator/config.py 最上面 import yaml
#   httpx        test_security.py 測 toolbox/gitlab.py 的分頁邏輯(_api_pages)時
#                用 monkeypatch 換掉 httpx.get,需要真的匯入得到這個套件
#   json-repair  agent.py 的 extract_json 退路(test_parsing.py 會驗到)
# 少任何一個,對應的測試檔是**收集階段就 ImportError**,不是某條斷言紅燈。
#
# sqlfluff 不一樣:只有 toolbox/sqltools.lint() 內部才 import,但預掃與整條審查的測試都會
# 跑到 lint。沒裝時 lint 在子行程裡失敗、記成「沒跑完」並交人工,那些測試是**斷言紅燈**
# (決策與報告跟著變),不是收集錯誤。
#
# 尚未加 pymssql:它是 spec_exec.execute_cases() 函式內部才 import(module 層不需要),
# 測試不連資料庫。哪天測試真的用到再加,不要先裝不用的。
#
# 驗證方式:用乾淨的虛擬環境只裝這份清單,跑 tests/ 應全數通過。
